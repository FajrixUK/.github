# Contributing to Fajrix

We welcome specific corrections, useful evidence and proposals that improve the clarity and quality of our public work. This is the default guidance for FajrixUK repositories that do not publish their own contribution instructions. Read the repository README for its purpose and scope.

## Discussing a change

Search existing issues and pull requests before opening a new one. Use the correction form for inaccurate wording, broken links, accessibility problems or presentation issues. Use the proposal form for an improvement, research question or relevant source.

For substantial changes, discuss the scope before preparing a large submission. Explain who would benefit and what evidence supports the proposal. Submission does not imply acceptance or a commitment to a release or response date.

## Preparing a pull request

Work on a branch in your fork, or an authorised branch in the repository. Keep each pull request focused on one coherent change. Describe the reason, affected material and checks performed.

For documentation, check facts against the cited sources and distinguish current capabilities from plans. Check links and previews. For visual changes, check desktop and mobile presentation and include an image description where appropriate. For software, follow the repository's build and test instructions and report the results and any limitations.

Include source links, dates and relevant passages for factual corrections. Verify AI-assisted work with the same care as other contributions; disclose material AI assistance and how it was checked. Never submit invented citations or unverified claims as established facts.

## Rights and provenance

Submit only material you have the right to share. Identify third-party sources, licence terms and modifications, and preserve required notices. Do not include confidential information, personal financial records, credentials or unpublished material belonging to someone else.

Follow the licence and contribution terms of the destination repository. Where it has no contribution licence, maintainers and the contributor must agree appropriate reuse terms before substantive external material is incorporated. A pull request does not transfer copyright ownership to Fajrix. The shared guidance here does not apply a licence to another repository or grant permission to reuse Fajrix branding.

## Review and conduct

Maintainers review changes for scope, accuracy, provenance and suitability. They may request revisions or decline a proposal. Please follow the [Fajrix code of conduct](https://github.com/FajrixUK/.github/blob/main/CODE_OF_CONDUCT.md).

Report security concerns privately using the [security policy](https://github.com/FajrixUK/.github/blob/main/SECURITY.md), rather than through a public issue or pull request. For other enquiries, see [support and contact](https://github.com/FajrixUK/.github/blob/main/SUPPORT.md).
